# Native conformance

The [catalog](catalog.json) inventories the pinned Claude Code and Codex event contracts, cross-cutting mechanics, existing evidence, and executable cases. Each event has separate trigger, payload, and output obligations. These are coverage obligations to refine into event-specific branches, not a claim that every behavior already has a fixture. The [compatibility contract](../docs/compatibility.md) owns the target versions and accepted V1 Stop exception; tests detect drift between those pins and this independent inventory. The catalog and this guide accompany the package; executing the development runner requires a repository checkout, including its scripts and test fixtures.

## Inventory and completeness

Run the inventory without native executables, a package build, or a model account:

```bash
node scripts/verify-conformance.mjs
node scripts/verify-conformance.mjs --require-complete --host v1
```

The second command writes its JSON report and exits with status 4 when the selected host profile is incomplete. A passing selected case does not clear other obligations, its whole event, or the other host. The report distinguishes requirements from evidence availability. Source-derived oracles, recorded fixtures, native references, native readers, host probes, and unit tests are indexed with their scope and artifact hashes. Their presence never becomes an automatic runtime pass.

V1 Stop rows carry the accepted exception and remain `exception-unverified` until expected rejection evidence is connected. V2 Stop remains a required native behavior. The initial runner does not execute the catalog's planned exception-evidence case. Testing an unsupported diagnostic for any other required capability does not establish native equivalence.

The statuses are `unverified`, `verified`, `failed`, and `exception-unverified`, per requirement and host. A fresh registered case can verify only its declared requirements at matching native and host versions. Runtime and comparison failures exit nonzero; they are not converted to successful diagnostic coverage. The report's `nativeConformant` field remains false while either target has missing proof or the full comparison retains a native exception.

## Independent native and host comparison

Build, then run the registered Claude PreToolUse control case:

```bash
npm ci
npm run build
node scripts/verify-conformance.mjs --case claude.pretooluse.control --claude-binary /path/to/claude --opencode-binary /path/to/opencode
```

Executable defaults are `CLAUDE_BINARY` or `claude`, and `OPENCODE_V1_BINARY` or `opencode`. The case requires the catalog's pinned Claude and V1 executables and POSIX process groups. It uses one unchanged synthetic hook script and source configuration in both runtimes, disposable HOME/config/project state, and deterministic loopback providers with synthetic credentials. It needs no real model account. V2 and Codex execution are not part of this case.

The native reference executes through Claude's actual CLI. The host reference loads the default package in the actual OpenCode server. Neither expected outcomes nor hook payloads come from the adapter's protocol interpreter or payload builder. The probe records source and hook digests and fingerprints the compiled adapter and package metadata, checking them again after execution.

The denied operation must invoke the owned hook once, prevent its marker-file write, and deliver the literal configured reason in a tool result on the next model request. An allowed control must invoke the same hook once, execute its marker-file write, and deliver no denial reason. Both must expose the expected event, native tool identity, cwd, and original command, a valid owned tool-call identity, the declared permission mode, and an existing transcript. A blocked operation with no hook invocation, two identically wrong observations, or a control that never executes cannot pass.

The allow control tests absence of a veto. It does not test an explicit native `permissionDecision: "allow"` overriding host permission policy. Native permission bypass and host permission allowance are fixture settings, not trust or approval conformance evidence. Machine-managed native settings can remain active. Observed native `/api/hello` requests receive 404 and are counted separately from model requests; unexpected routes fail the probe.

The comparison publishes the exact set of selected observables. It does not normalize arbitrary payloads into equality. Full input schemas, extra fields, reminder wrapping, transcript contents, model roles, warnings, and rendering remain separate unverified obligations. Native session and call identifiers are checked against their own invocation rather than forced to match identifiers generated by another harness. Provider traffic, raw hook payloads, native output, and temporary filesystem paths are not printed. Temporary fixture state and child process groups are cleaned up on success or failure.

Use the complete-profile gate with the same case to retain a passing narrow result while still rejecting incomplete conformance:

```bash
node scripts/verify-conformance.mjs --case claude.pretooluse.control --require-complete
```

## Extending the suite

Add a stable requirement for each independently testable native behavior and register a case with explicit source dialect, supported host targets, and observables. Broad event obligations need native branch coverage before they can be declared verified; a single example is insufficient. Reconcile version-sensitive behavior with the pinned native release, using public documentation as a starting reference rather than runtime proof.

Native and host observers must collect actual effects independently. Preserve dialect differences such as Claude feedback versus Codex result replacement. Use literal positive and negative controls, then generate malformed inputs and state sequences around the established contract. Validate only incidental identity differences, preserving required relationships, exact owned text, role, ordering, invocation counts, and side effects. Do not use the production translator to manufacture expected values.

Add a regression that fails when a real observable is lost or changed, including controls against vacuous passes. Record native/host versions, platform, fixture identity, source integrity, and supported scope. Map older probes as evidence available until their results have an explicit validated comparison path. Keep private installation policies as a separate migration acceptance suite.

## CLI contract

Help is available with `-h` and `--help`. Options support short and long forms, attached values, `--name=value`, short bundles, and `--` as the end of options; positional arguments are not accepted. Inventory performs no hook or host execution. The case runner checks conditional dependencies and exact versions before fixture execution. The inventory reads repository-contained regular evidence files and does not follow evidence outside the checkout.

Results are JSON on stdout. Diagnostics are on stderr without provider traffic or local paths. Exit status 0 means inventory or selected-case success, 1 means runtime/comparison failure, 2 means usage/version/platform preconditions, 3 means missing executables or build, and 4 means the requested completeness gate is not satisfied while its report is preserved.
