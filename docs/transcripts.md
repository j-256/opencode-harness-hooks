# Claude transcript projection

The default V1 and V2 entrypoints can supply a Claude-format JSONL transcript for the supported text, tool history, observed model dates and admitted foreground command prompt-attachment subset. V1 reads session metadata and the complete unpaginated message response through its native SDK. V2 reads session metadata and the active context through its plugin session API. The service checks session identity and content before publishing a file. It does not label an arbitrary host history dump as a Claude transcript.

## Representation and timing

Projected records use Claude's `user` and `assistant` message envelopes, a linked `parentUuid` chain, stable derived UUIDs, host timestamps, host session identity, project directory and the pinned Claude format version. User text remains user content. Assistant text and tool-use blocks preserve order, model identity and correlated tool IDs. Known host tool names and inputs use the shared native tool schema translation. Completed tool results become correlated user `tool_result` blocks, including the error flag for host failures. Usage and native request telemetry are omitted when a compatible source value has not been established.

The service observes original arguments before input rewriting, including calls that do not match a Claude registration. Later projections retain those original arguments when the host has stored the effective arguments instead. An unobserved historical tool call fails with `TRANSCRIPT_ORIGINAL_INPUT_UNAVAILABLE`; a cold resume cannot silently replace missing original arguments with an assumption.

Pinned native command-hook captures establish that a transcript can be absent at `SessionStart` and `UserPromptSubmit`, exists before `PreToolUse`, and does not yet contain the current result during `PostToolUse`. The projection therefore includes the current assistant tool-use block and omits that call's result during the tool hooks. Earlier completed results remain visible. A first prompt reserves its stable path without creating an empty transcript; later prompt hooks read the preceding text/tool history before the submitted message is admitted. A history that already contains the submitted message fails with `TRANSCRIPT_PROMPT_ALREADY_ADMITTED`. An empty history after publication fails with `TRANSCRIPT_HISTORY_RESET_UNVERIFIED` instead of reusing a stale file. This timing observation covers the exercised native command/MCP and prompt flows; it is not a complete lifecycle timing contract.

An independent native Claude resume experiment reads projected text/tool histories from both pinned OpenCode hosts and includes their prompt, tool-call and earlier failure content in the resumed model request. This establishes acceptance by the exercised native reader. It does not prove byte identity, all transcript consumers, or unsupported content. The default-package probe separately proves that an actual native-contract hook can read the generated file before deciding whether to deny or rewrite a tool call. Portable regeneration of the independent native reader capture remains a conformance gate.

## V2 completion snapshots

The explicit core service can prepare a V2 `StopEvent` before its command hooks execute. The event identifies the original user message and the completed assistant message. Preparation validates the working directory, turn and final completion against native history, then includes the complete assistant response and earlier completed tool results without requiring a current tool call. Original tool arguments and observed model-date requirements remain enforced. Queued preparation captures the event identity before caller mutation, and a replacement user turn cancels the read even when the caller's own signal remains live.

A core I/O fixture runs an unchanged command registration which reads the resulting Claude envelopes through its `transcript_path` payload and returns a Stop decision. This covers preparation before the initial Stop batch. The explicit `admitStop()` service retains the exercised command-output records against that prepared assistant snapshot, including feedback which another hook prevents from continuing. Empty/plain and structured output, warning/context records, stderr feedback, native validation and nonblocking failures, and timeout records use their separate observed forms. Later snapshots preserve native order within each handler result, summary fields, shared batch identity and parent links. Missing preparation, repeated admission, stale turns, cancellation, unsupported artifacts and changed or pruned retained completions reject without partially admitting records. Limits bound prepared completions, records and bytes; session closure and disposal release them.

The explicit service can bind a normalized V2 synthetic readback to an admitted continuing Stop. That exact owned row retains the original logical turn; projection omits its transport marker and keeps the native Stop records plus following assistant history. Ownership fingerprints include the complete readback, and the row must follow its originating assistant. Unknown, changed, moved or pruned synthetic rows fail. This bounded primitive does not supply transactional SDK admission or enable the default V2 adapter. Complete native identity metadata, all malformed-JSON syntax diagnostics, asynchronous promotion, signal and spawn-failure mappings, noncommand artifacts and default-root model delivery remain required conformance gates. This service rejects V1 Stop preparation and admission under the accepted host exception. See [Stop coordination and native reference](stop.md).

An isolated Claude Code 2.1.318 resume-reader capture accepts this admitted subset and preserves the owned feedback and reminder roles, ordering and exact text. The reference uses native records through the first Stop summary, so later native continuation responses do not enter this focused record comparison. Only corresponding executed-command displays are substituted; whitespace and suppressed feedback remain significant. Portable regeneration of this reader comparison and complete host continuation delivery remain conformance gates.

## Admitted prompt attachments

Successful foreground Claude command hooks can contribute native `hook_success`, `hook_system_message` and `hook_additional_context` records at `UserPromptSubmit`. They follow the original user record in hook completion order and precede its assistant response. Original user text remains unchanged. Stdout and warning records share the prompt event's hook identifier; additional-context records have independent `hook-` identifiers. Every attachment retains a stable identity across repeated snapshots. Duplicate registrations retain independent records and outputs under the bridge's no-deduplication contract.

Ordinary nonblocking command failures contribute `hook_non_blocking_error` records with the native error prefix, trimmed stderr or the native empty-stderr fallback, raw stdout, numeric exit code, executed command and duration. They share the prompt event's hook identifier and retain their completion order. These records have no model rendering; failure stdout and stderr do not become model context. The handler and dispatch diagnostics still report the failure. Valid structured JSON output can produce warning and additional-context records despite a nonzero exit, matching the pinned native parser. The projection preserves those interpreted effects rather than replacing them with an error record.

Timed-out foreground commands contribute native `hook_cancelled` records with `timedOut: true`, the effective deadline in milliseconds, the executed command and measured duration. Their stdout, stderr and eventual process exit are omitted from the attachment and model context. The deadline comes from the prepared execution, including any explicit shared budget; it is not inferred from elapsed time. A timeout with unavailable deadline evidence fails explicitly. A blocking decision, blocking failure policy or cancelled turn still prevents prompt admission.

The pinned POSIX captures also establish native exit code `1` for direct SIGTERM, SIGINT and SIGKILL terminations and for a shell terminating itself with SIGTERM. Ordinary failures under those observed signals use the native error record while preserving the actual signal and nullable process exit in private execution evidence. Valid structured JSON followed by SIGTERM retains its interpreted context. Other signal values lack a verified attachment mapping and fail explicitly.

The stdout attachment includes the actual executed command display, raw stdout/stderr, exit code and measured duration. Hook completion times supply its timestamp. Additional-context attachment timestamps use the bridge's completed prompt batch time. These are observed bridge execution times, distinct from host message timestamps; a host that admits its user record after hooks finish can have earlier attachment timestamps. Native request telemetry, environment values and hook stdin are not fabricated or added to attachment data. General diagnostics still exclude command/output data. The default runtime opts into command artifact capture only for its prompt transcript consumer; the library's explicit `HostServices.captureCommandArtifacts` option exposes that private execution data and its effective `timeoutMs` in handler results, outside diagnostics.

`TranscriptService.admitPrompt()` is an optional synchronous admission interface. The root calls it after accepting the resolved prompt effects. Records are staged privately and become visible only when host history contains that admitted user-message ID and its original text. A tracked history without an admission receipt, or with changed prompt text, fails with `TRANSCRIPT_PROMPT_HISTORY_UNAVAILABLE`. Stale, repeated, foreign and cancelled admissions fail without replacing accepted records. Session closure and plugin disposal remove retained attachment state. Named limits bound tracked sessions, turns, attachment records and retained bytes.

An independent native resume-reader probe accepts generated attachments from both host projections. The resulting provider requests preserve native user-role rendering before the original prompt, completion order and duplicate context, while warning and raw stderr fields stay out of model context. Controlled native record removal and addition isolate a rendering dependency: omitting the native date attachment adds a newline to the final hook-context block during resumption. The projection supplies observed date records, and the strict native fixture compares exact context text without trimming that newline or any other content. Warning delivery in the root still requires its explicit effect service; writing a warning attachment does not implement that user-interface effect.

## Observed model dates

V1's `chat.headers` and V2's primary `model.request` callback record actual model-preparation time through `TranscriptService.observeModel()`. These callbacks also run for selected Claude tool-only configurations. The pinned native runtime uses the process-local calendar date: controlled UTC and offset-timezone captures distinguish it from a UTC-only conversion. Same-day requests and turns coalesce into one date attachment per session; a different local date on a later turn adds a new record. The projection places that record after the admitted user and hook context, before the corresponding assistant message, with the native date content and rendering. Its identity and observed timestamp remain stable during later reads.

A turn with model history requires an observation receipt. Missing observations produce `TRANSCRIPT_MODEL_CONTEXT_UNAVAILABLE`; the service does not infer a date from historical message timestamps or the clock at transcript-read time. A user message without model history does not require a fabricated date. V1 binds observation to its native user-message ID. V2 binds primary requests to the preceding validated context's user ID and turn lifetime, so a late context or model callback cannot record a date for the next user turn. Session closure and disposal release the bounded calendar state.

The library exposes `createRuntime().observeModel()` and the `HostModelEvent` type for callers supplying their own host integration. `ClaudeTranscript` accepts an explicit `now` clock for controlled tests; the default reads the host clock at model preparation. A calendar change within one active user turn remains `TRANSCRIPT_DATE_BOUNDARY_UNVERIFIED`: insertion among that turn's assistant and tool records needs separate native ordering evidence. Cold resume and cross-activation calendar recovery remain unfinished. These explicit limits are not successful native equivalence cases.

Artifact observation failures have a distinct metadata-only diagnostic with host, artifact, phase, session/message IDs, code, outcome and duration. `RuntimeServices.artifactDiagnostic` can observe it. The runtime excludes exception text and contains observer failures without changing the original error; it does not mislabel a tool-only artifact failure as `UserPromptSubmit`.

## Limits and ownership

The supported projection deliberately rejects host content that lacks a verified mapping. Host attachments, reasoning, unowned synthetic messages, skills, shell-message records, compaction, location changes, unknown tool states and unknown finish reasons are unsupported. Unverified termination signals, malformed hook output, unavailable execution evidence, other handler families, background work and other lifecycle events need separate attachment mappings and fail explicitly when required for prompt admission. A blocking prompt is never admitted as a nonblocking failure. V2's active context is not assumed to contain the full pre-compaction history. Unsupported history prevents execution of the matching Claude hook; an older artifact is not substituted. Full native transcript equivalence, cold resume, subagent semantics, remaining native hook/auxiliary records and Codex rollout artifacts remain acceptance gates.

Named limits in [the implementation](../src/transcript.ts) bound history-read time, messages, serialized bytes, observed-call memory and pending snapshots. Exceeding a limit produces a specific diagnostic; history is not truncated to make a projection succeed. Snapshots for one session serialize their reads and atomic file replacement. Each request still runs, and this serialization does not deduplicate source registrations or hook executions.

The service creates its own temporary directory with mode `0700` and files with mode `0600`. Session IDs are hashed for filenames. A hook sees a stable path during that plugin activation. Atomic replacement gives newly opened readers a complete snapshot, but append-only tailing and inode continuity are not established native-equivalent behaviors. Disposal cancels pending work, drains the projection queue and removes the owned directory. A process crash can leave a private temporary directory for normal operating-system or user cleanup. These derived files do not replace the host's durable conversation store.

`RuntimeServices.transcripts` permits an explicit implementation with the same observation, preparation and disposal contract. The runtime owns that service's lifetime. A supplied native metadata callback can provide its own verified transcript path instead of requesting the default projection. The payload builder does not validate an externally supplied artifact's contents. Default-package reports retain `equivalent: false` while the complete native artifact and migration requirements remain unresolved. Native environment-file persistence is a separate, unfinished service.

## Reproduction

The package probe can exercise either native dialect on either host:

```sh
npm run build
npm run test:host:plugin -- --host v1 --dialect claude-code --binary /path/to/v1/opencode
npm run test:host:plugin -- --host v2 --dialect claude-code --binary /path/to/v2/opencode
```

The fixture hook reads its transcript, checks the current original command and user prompt, denies one file write and replaces a subsequent command. Fixture temporary files include the projected transcript and are removed with the isolated project. The default dialect remains `codex`; its nullable transcript behavior is unchanged.

`--dialect mixed` loads the same synthetic file and command as independent Claude and Codex sources. Each controlled call must produce one native-format invocation per source, including the Claude transcript check. Both hosts retain the denied side effect's absence and execute the agreed rewrite. This proves the exercised source mixing and lack of command deduplication; it does not assert that duplicate private policies have composable side effects.

## Native oracle and reader verification

From a repository checkout, build and run the independent native fixture:

```sh
npm run build
npm run test:native:claude -- --binary /path/to/claude
```

The verifier requires the pinned Claude Code executable, Node.js and POSIX process groups. `-h`/`--help`, `-b`/`--binary` and `CLAUDE_BINARY` are supported. It uses isolated HOME/config/project state, synthetic credentials and a loopback Anthropic provider, preserving an explicitly configured `TZ` for both the bridge and native child. Native hooks capture their actual transcript before a controlled file read. Distinct commands returning identical context establish attachment shapes, completion order, exec argument display and model delivery. Nonblocking failures exercise populated and whitespace-only stderr; valid structured output on a nonzero exit independently exercises native warning/context preservation. Fractional command timeouts and the observed direct terminating signals exercise native cancellation/error fields and exclusion of their output from model delivery, including structured context followed by SIGTERM. A separate timeout control proves that an `onFailure: "block"` hook executes and prevents a model request. A byte-identical registration control measures native command execution collapse. The built bridge preserves each selected registration, compares its supported attachment fields and observed local date format to the native capture, then resumes both host-format projections through the native CLI. Fresh native delivery and native transcript resumption have separate captures: projected resumption compares exact context text, including reader-added whitespace, against native transcript resumption. Identifier, timestamp and duration values are checked for their required structure and relationships rather than byte equality. The error-record field comparison groups failures by fixture identity because independent native and bridge processes can complete in a different order; the bridge's own completion order is checked separately.

JSON output reports both reader outcomes, exact context-text comparisons, required failures and the native/bridge repeated-command difference, retaining `equivalent: false`. It exposes no source commands, local paths, hook output or provider traffic. Exit statuses are `0` for the exercised checks, `1` for a runtime or assertion failure, `2` for usage/version/platform preconditions, `3` for a missing binary or build and `4` for required reader fidelity differences. Status `4` preserves the JSON report on stdout. The verifier installs nothing, changes no live configuration and removes its own temporary state. Its evidence covers these synthetic prompt records, not all native artifacts or the complete native identity algorithm.
