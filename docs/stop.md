# Stop reference and integration gates

OpenCode V1 rejects configurations containing enabled Stop registrations under the accepted [V1 compatibility exception](compatibility.md#v1-stop-exception). The default V2 entrypoint connects awaited idle, Claude command execution, native transcript records and exact model continuation for the foreground fixture described below. Complete V2 Stop parity remains required; this exercised subset does not make the package ready to replace an existing hook integration.

## Explicit core coordination

The V2 core API accepts `RuntimeServices.stop` with a required `admit` service. Call `runtime.stop(event)` with the host, `event: "Stop"`, session ID, original user `messageID`, unique assistant `completionID`, working directory and native metadata in `data` or `dialectData`. The coordinator supplies the active turn identity and its own `stop_hook_active` flag. Conflicting supplied identities or active flags fail. Matching executable handlers have required metadata preflighted before dispatch, including the last assistant text and Claude's transcript, background-task and session-cron fields. Supplied artifacts and metadata remain the caller's responsibility and must be compatible with the native consumers.

The service receives the immutable event, originating session snapshot, attributed dispatch, resolved effects and cancellation signal. It must admit native artifacts and deliver every effect, or reject. Command execution artifacts remain private inputs to that service. A callback which discards them does not establish parity. Successful admission returns a metadata-only receipt with `continue`, `complete` or `stop` control; a successful feedback admission makes the next Stop in that logical turn active. A new real prompt resets that state. `continue: false` prevents continuation without permanently closing the session to later prompts. If explicit startup coordination is configured, Stop waits for its admission before running commands.

`ClaudeTranscript.prepare()` can supply the initial V2 [completion snapshot](transcripts.md#v2-completion-snapshots) before dispatch when called with the Stop event and its originating session. The caller still supplies the remaining native metadata and the admission service. Preparation alone does not create Stop summaries or feedback records.

An explicit core admission service can call `ClaudeTranscript.admitStop(delivery)` to retain the exercised Claude command records. This requires a prepared completion snapshot. The command projection covers empty and plain stdout, structured output, warnings, JSON and stderr feedback, continuation prevention, nonblocking process and validation errors, and timeouts. It preserves raw execution fields and the native distinction between structured and plain output on nonzero exits. The next `prepare()` inserts records after their original assistant and before a later real prompt. Separate suppressed feedback, shared batch identity, summary information and parent links remain intact. Repeated admission, changed or pruned completed history, stale turns, cancellation and unsupported artifacts reject without partially admitting records. Session closure and disposal release the bounded retained state. This method handles Claude records; a service using other dialects or effects must deliver those separately.

Admission returns an immutable array of native user-text blocks derived from the retained records. Rendered reminders precede meta feedback, with the observed separating newlines. Suppressed reminders and feedback remain available for later history; receiving this array does not authorize continuation. The caller must honor the coordinator's control decision. The internal [provider transport](prompts.md#host-transport) can replace an explicitly owned synthetic user's marker with these blocks while preserving the original turn and prompt context. It validates the raw marker and complete history layout before replacement.

After an admitted continuing Stop, the explicit service can bind a normalized V2 history readback with `ClaudeTranscript.admitContinuation(delivery, readback)`. This retains one immutable readback fingerprint per completed Stop, under its original prompt and session lifetime. History normalization accepts that exact synthetic row immediately after its originating assistant. Changed content or metadata, moved/pruned history, reused identities, cancellation and foreign owners fail. The translated transcript keeps the native Stop records and following assistant responses while omitting the raw transport marker. An unowned synthetic row still fails. Readback bytes share the existing Stop budget and session cleanup.

`ClaudeTranscript.reserveContinuation(delivery, input)` reserves that ownership and its readback budget before SDK mutation. The input declares the ID, text, metadata and optional description; its identity and session snapshot are captured before returning. The reservation's `admit(readback)` requires that exact payload plus the native type and creation time. Unknown fields reject. A named allowance bounds the normalization fields which are unavailable before the next context phase, and admission replaces the allowance with the actual readback charge. `release()` frees an unadmitted reservation without erasing committed history. Cancellation releases pending ownership; session closure and disposal detach its listeners and clear retained state. Direct admission remains available when readback already exists. These primitives reserve transcript and model resources separately; production queued-state and cancellation reconciliation remain required.

Unmapped malformed-JSON syntax, output-driven asynchronous promotion, termination signals, spawn-failure artifacts, native identity metadata beyond the shared transcript envelope, noncommand artifacts and complete transactional host admission remain required gates. These unsupported artifacts reject; they are not successful equivalence cases or additional accepted exceptions. Continuation ownership does not turn synthetic input into a real prompt or replay prompt hooks.

Repeated delivery of the same completion identity joins its existing work or receipt. Different content under that identity, stale turns and overlapping different completions fail. This delivery guard does not deduplicate registrations. Native nonblocking failures and native skipped handlers retain their outcome; unsupported handlers prevent admission. Named limits in [the coordinator](../src/stop.ts) bound retained completions, metadata and service time. Diagnostics contain correlated IDs, stable codes, phase and duration, excluding payloads, commands and output.

New prompts, session closure and disposal cancel pending work. Admission services must honor their cancellation signal before committing effects. An admission which remains pending after timeout or cancellation retains the session's completion lock, including across prompt replacement. Disposal tracks those underlying promises, reports `HOST_STOP_ADMISSION_DRAIN_FAILED` if they remain pending beyond the service timeout, and permits a cleanup retry. Cancellation alone does not establish successful drain.

## Default V2 integration

The default V2 factory owns its Stop admission service and rejects an injected core service with `HOST_STOP_HOST_UNAVAILABLE`. Enabled Stop requires the pinned OpenCode 2.2.5 version and native session get, context and synthetic APIs. Missing version or APIs fail activation. Codex Stop fails activation with `HOST_STOP_DIALECT_UNAVAILABLE` until native rollout and model projection are implemented. V1 retains its configuration-specific `HOST_STOP_UNSUPPORTED` rejection, including when a core Stop service is supplied.

The adapter reads native history before dispatch, requires an original user turn and one terminal assistant text part, and rejects subagent histories and nonempty background work before command side effects. The foreground fixture declares empty cron metadata; broader scheduler semantics remain unproved. The command reads its prepared Claude transcript and may request continuation. The adapter reserves transcript and model ownership before calling the SDK with an explicit message ID, provenance and a private transport marker. It validates the queued acknowledgement and waits for the following context phase to validate normalized readback before admitting either reservation. Model transport replaces only that owned marker with exact native feedback/reminder blocks. The next Stop snapshot contains native records and assistant history without the marker. Repeated registrations remain independent.

Unmapped warnings and extension effects fail explicitly. Prevention does not enqueue a corrective prompt; native retained model artifacts without an owned continuation cause a later prompt to fail with `HOST_STOP_HISTORY_PROJECTION_UNAVAILABLE`. Historical insertion for that path remains required. New prompts cancel pending admission; late SDK results remain quarantined and cannot reach model delivery. This fail-closed behavior is not native cancellation parity or recovery.

Disposal tracks the raw SDK submission rather than declaring an observation timeout to be a drained operation. A failed drain retains callback guards and permits retry after actual settlement. Draining submissions does not remove already accepted native inbox inputs. Accepted-input cancellation, disposal/reload reconciliation, cold resume, complete background/subagent/cron metadata and complete artifact/effect delivery remain required. These are unfinished acceptance gates, not further exceptions to the parity requirement.

## Independent native reference

`scripts/verify-native-stop.mjs` exercises Claude Code 2.1.318 and Codex 0.167.0 through their actual command-line runtimes. Each generated source config contains one command Stop registration and remains unchanged during that case. The fixture covers JSON `decision: "block"`, blocking stderr with exit code two, a failing command configured with `onFailure: "block"`, and `continue: false` with a stop reason.

JSON block and exit-code-two feedback cause another model response in the same turn. The first Stop payload has `stop_hook_active: false`; the continued pass has `true`, preserves session and turn/prompt identity, and supplies the updated last assistant message. The fixture checks the hook payload's working directory and transcript availability, that the next model waits for the command, and that CLI completion waits for the final Stop command. A nonblocking command failure does not become a continuation even when its configuration requests failure blocking at this event.

Claude's JSON block produces a `hook_blocking_error` attachment and a meta user feedback record. The feedback record precedes that attachment in the transcript, while the next model receives the rendered blocking-error reminder before the feedback text. Blocking stderr instead prefixes feedback with the command and creates no equivalent blocking-error attachment. Nonblocking failures retain their native error attachment. `continue: false` produces a stopped-continuation attachment followed by the command success attachment and a summary with the prevention flag. The fixture checks native Stop summaries, exact owned error content, field presence, record order and batch identity.

Codex delivers both blocking paths as a user message wrapped in `hook_prompt`, with a run identity containing the native Stop prefix and source config path. Its rollout retains a corresponding `HookPrompt` item, message identity, turn identity and harness provenance. The fixture compares the rollout and provider request, including their order after the prior assistant response. Claude feedback and Codex hook prompts require separate translation; passing the unrendered reason to a host synthetic-message API is insufficient.

The fixture isolates HOME, configuration and project state, uses synthetic credentials and a loopback provider, bounds subprocesses and artifacts, and removes temporary state. Isolation does not remove machine-managed native settings. Claude Stop summaries report additional native handlers separately from the exact generated command. Unexpected aggregate effects still fail the controlled assertions. Codex's controlled fixture explicitly bypasses hook trust and can emit startup diagnostics for that bypass and the synthetic model; their item count is reported. These observations do not establish native trust, managed-policy or complete artifact parity.

## Additional Claude output cases

Claude Code 2.1.318 accepts a parsed `decision: "approve"` at Stop without turning it into an approval or continuation. Empty `additionalContext` does not continue the turn, while whitespace context remains significant. An empty or missing block reason continues with the native fallback `Blocked by hook`; a whitespace reason is preserved. Blocking stderr is preserved without trimming and uses `No stderr output` only when empty. An empty or missing prevention reason uses `Stop hook prevented continuation`. Empty warnings are ignored, while whitespace warnings remain significant. Prevention retains accompanying decisions, warnings and context for artifact admission even though model continuation is suppressed. The [focused interpreter cases](../test/protocol.test.ts) retain these observed Stop distinctions.

The `--outputs` fixture checks the [native command-output oracle](../test/fixtures/claude-stop-output-oracle.json) against the actual Claude runtime, including exact record bodies, summary fields, model text and envelope ownership. Corresponding command displays, batch/prompt IDs and measured durations are the enumerated substitutions; duration presence, raw output, roles, whitespace and error details remain significant. Native event-name failures discard stdout and record exit code one, even when the command exits two. Schema failures retain raw stdout and the process exit, with a distinct stderr suffix for nonzero failures. Stop validation strips fields belonging to other events and preserves the native validation descriptions using the matching Zod schema/version. This decoder applies to Stop; it does not establish other events' host integration.

Interpreted Claude Stop continuations retain `channel: "decision"`, `"stderr"` or `"additionalContext"` through shared dispatch and effect resolution. Identical text can come from different fields, including two fields in the same handler result. Artifact delivery needs that distinction: additional context produces a native reminder block, while blocking decisions and stderr produce Stop feedback. Other handlers do not acquire a channel inferred from their text; model verdicts remain distinct from process stderr.

The `--aggregation` fixture regenerates [command aggregation observations](../test/fixtures/claude-stop-aggregation-oracle.json) with handlers that complete in a different order from their configuration. Claude retains separate meta feedback records in completion order, including when another handler prevents continuation, and selects the last completed stop request's reason. In the cases combining blocking feedback and prevention, its CLI result is empty even though the transcript retains the preceding assistant answer. Codex combines blocking fragments in configuration order and creates no HookPrompt when another handler prevents continuation. Its fixture does not expose the competing stop reasons. Native retained artifacts remain separate from the resolved permission to continue.

The core preserves these continuation orders. With mixed sources, Claude continuations occupy Claude's configured positions in completion order, and Codex positions remain fixed. Any stop request suppresses all continuation delivery while retaining the attributed dispatch for artifact admission. The earliest configured stop request selects which dialect supplies the reason: Claude uses its last completed stop request, and Codex uses its first configured request as an explicit bridge rule. The Codex rule does not claim independently observed native reason selection. These combination rules apply to Stop; they do not infer SubagentStop behavior.

## Reproduction

From a repository checkout with Node.js 22+, POSIX process groups and the selected pinned executable:

```sh
npm run test:native:stop -- --dialect claude-code --binary /path/to/claude
npm run test:native:stop -- --dialect codex --binary /path/to/codex
npm run test:native:stop -- --aggregation --dialect claude-code --binary /path/to/claude
npm run test:native:stop -- --aggregation --dialect codex --binary /path/to/codex
npm run test:native:stop -- --outputs --binary /path/to/claude
npm run build
npm run test:host:v2:stop -- --binary /path/to/v2/opencode
npm run test:host:v2:stop -- --default-root --binary /path/to/v2/opencode
```

The command supports `-h`/`--help`, `-d`/`--dialect`, `-b`/`--binary`, `--aggregation`, `--outputs`, `CLAUDE_BINARY` and `CODEX_BINARY`. The dialect defaults to `claude-code`. Output characterization requires Claude and cannot combine with aggregation. Generated command scripts pass a syntax check before native execution, and output-characterization waits enforce the timing deadline used by the assertions. The probe requires no package build, model account, installation or live configuration change. Metadata-only JSON goes to stdout; diagnostics go to stderr without commands, outputs, native payloads or local paths. Exit statuses are zero for passing native checks, one for runtime/check failures, two for usage/version/platform preconditions and three for a missing executable.

The native reference result retains `bridgeStopComparison: "not-implemented"` and `equivalent: false`. Complete V2 cancellation, repeated decisions, background work, subagent completion, remaining handler families and the private migration comparison remain required gates. The V1 exception does not waive these V2 requirements.

The V2 core probe separately connects the explicit runtime, command execution, transcript admission, owned synthetic readback and provider transport against OpenCode 2.2.5. It checks the same-turn active transition, unchanged source bytes, expected native user-text blocks, retention through the next Stop snapshot and private-header removal. Transcript ownership, a model-input slot and an explicit message ID are reserved before SDK mutation. The queued acknowledgement must preserve the requested identity, session, payload and delivery. The exercised host queues that identity during idle; immediate history lacks its row, and the following context phase supplies the normalized readback for admission through both reservations. The probe checks both phases instead of assuming the SDK return value is durable history. It uses a foreground fixture with declared empty background/cron metadata. Its report retains `defaultRootStop: false` and `equivalent: false`.

Adding `--default-root` runs the same unchanged command source through the actual package entrypoint. An independent observer records native prompt/context/idle identities and labels loopback requests; it does not inject services, dispatch hooks or translate messages. This profile checks provider text, retained transcript records, queued/readback phases and absent marker leakage through the production adapter. Its report sets `defaultPackageEntrypoint`, `independentObserver` and `defaultRootStop` to true while retaining `equivalent: false`. Neither profile completes the remaining integration gates. Help needs no build; execution needs the built package, Node.js 22+, POSIX, Git and the pinned host. Exit statuses follow the native probe's zero/one/two/three convention.
