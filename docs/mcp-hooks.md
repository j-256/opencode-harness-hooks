# MCP hook execution boundaries

The engine's MCP service interface preserves the requested raw server/tool identity, expanded input, connection policy, authentication restrictions, and timeout contract. Stock V1 can execute its configured MCP tools through an owned SDK session with a deterministic provider transport. The default V1 plugin binds this service for enabled MCP registrations unless an explicit custom service owns execution. It uses no model account or provider network request. Recognizing a source registration or having a callable tool is not full native conformance.

## Canonical tool identity

V1 flattens a raw server and tool into one name, replacing characters outside ASCII letters, digits, underscores, and hyphens with underscores. Its public model catalog and tool callbacks expose the flattened name. See the pinned [MCP catalog implementation](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/opencode/src/mcp/catalog.ts).

A controlled collision demonstrates the lost identity: the source requests `fixture` / `check_read`, and native Claude calls `check_read`; the same flat V1 name selects `check.read` when those definitions collide. The [captured observations](../test/fixtures/v1-mcp-boundaries.json) record both actual RPC tool names. Sending a guessed flat name can execute a different operation.

The guarded helper permits server and tool names containing only ASCII letters, digits, and hyphens. Their host name has one unambiguous underscore separator. A complete raw server inventory can also verify wider server names when exactly one configured server can own the flattened target. Tool names outside the injective subset, and unresolved server aliases, report `HOST_MCP_TOOL_IDENTITY_UNAVAILABLE` before delegation. A wider safe subset requires authoritative raw identity information or a direct configured-client invocation boundary; absence of a collision in a sample is insufficient.

## Native request metadata

The pinned Codex executor adds the native session identity as `_meta.threadId` on each tool call. An isolated native invocation captures that field alongside the generated progress token. The stock V1 model-tool path supplies its own progress token and has no public per-call request-metadata parameter. A service must preserve the engine request's `metadata.threadId`; a default adapter cannot claim Codex MCP parity by placing it inside tool arguments or substituting a host session ID. See the [pinned Codex executor](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/core/src/hook_mcp_executor.rs).

## Raw MCP output

Native Claude treats an MCP error result as nonblocking failure and ignores structured-only results as hook text. Multiple text blocks can supply a JSON policy. V1's [tool conversion](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/opencode/src/mcp/catalog.ts) synthesizes a JSON text block when `content` is empty and non-null `structuredContent` exists. This happens before its public tool-after callback. The [captured public callback](../test/fixtures/v1-mcp-boundaries.json) records the synthesized policy text.

The callback cannot distinguish synthesized text from genuinely supplied identical text plus the same structured data. Publishing that text as a native hook policy could deny an operation that native Claude permits. The guarded helper reports `HOST_MCP_RAW_OUTPUT_UNAVAILABLE` for that ambiguous shape, while preserving unambiguous text, empty text, and MCP error semantics. Source arguments and raw results are copied within byte limits; partial or malformed results cannot publish policies.

The [protocol controls](../test/v1-mcp-protocol.test.ts) cover the identity and output guards. These observations establish specific host losses. They do not establish complete connection readiness, authentication, elicitation accounting, rendering, lifecycle, V2, or full MCP conformance. Those remain separate implementation and proof obligations.

## Owned V1 backend

The internal [V1 MCP backend](../src/hosts/mcp-v1.ts) reuses owned session creation, callback binding, cancellation, and cleanup with a separate MCP execution policy. It registers an in-memory private provider and hidden actor, verifies a deny-all/allow-target child policy, and emits a deterministic request for the exact copied tool arguments. The provider makes no model or provider network call. Ordinary requests cannot use it as an execution authority. The result must belong to the known child, call, and observed assistant, followed by the exact owned completion fence; an unrelated SDK error cannot publish it.

The backend accepts only configured servers whose canonical identity can be verified. Disabled or authentication-required servers do not trigger connection or authentication endpoints. A failed cached connection can be retried under the requested Claude policy; observational connection attempts run without delaying the hook and retain bounded diagnostics. Repeated requests share one in-flight observational reconnect per server, simultaneous background connections have a global resource bound, and disposal cancels their work. Late status replies cannot initiate reconnection after cancellation. Native request metadata that the public host path cannot supply reports `HOST_MCP_REQUEST_METADATA_UNAVAILABLE` before connection work or delegation.

Private tool callbacks bypass native hook recursion and parent history. An unexpected permission request aborts the owned child. Request readers, synthetic responses, copied arguments, raw results, and active operations have bounds. Cancellation uses a fresh cleanup scope, and failed deletion receipts remain inspectable for disposal retry. Connection diagnostics identify the operation, parent session, outcome, and duration without arguments or server errors.

The [backend tests](../test/v1-mcp-service.test.ts) and [transport controls](../test/v1-mcp-transport.test.ts) cover these boundaries. The [default binding controls](../test/plugin-mcp.test.ts) verify private callback routing, source-hook suppression, parent denial, custom ownership, and disabled-source behavior. The in-memory private provider is added to an existing provider allowlist without admitting other providers; explicit disablement of that reserved provider fails configuration. Disposal restores an owned allowlist change.

The registered `claude.pretooluse.mcp` comparison runs the same source, command hook, and local MCP server bytes under pinned native Claude and stock V1. It checks literal arguments, parent effects and denial feedback, successful and multiple-text decisions, nonblocking tool errors, empty/malformed text and timeout, source callback counts, parent transcript isolation, and child cleanup. Run it using the [conformance guide](../conformance/README.md). Connection/authentication/elicitation, exact raw multi-text whitespace, other events, providers, native trust, and V2 remain separate implementation and proof obligations. A passing bounded comparison does not establish full MCP conformance.
