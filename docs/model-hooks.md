# Prompt hook model services

The engine accepts an explicit `HostServices.evaluatePrompt` callback. It receives the substituted hook prompt, source-native event data within that prompt, the requested native model when present, and a cancellation signal bounded by the handler deadline. The callback returns a decision with `ok`, a string `reason` when denying, and an optional Boolean `impossible`. Native per-event control remains in the engine; callback presence alone does not establish model, context, authentication or lifecycle equivalence. Default V1 evaluator-session binding remains a separate integration step, and agent/MCP services retain their own requirements.

`captureModelArtifacts` opts into private prompt-model execution evidence. It does not classify a model call as a command invocation. The default runtime requests this evidence when a transcript service admits prompt submissions. Successful `UserPromptSubmit` evaluation adds no attachment, and a prompt-model timeout remains nonblocking without a timeout attachment. A malformed verdict produces the measured Claude Code 2.1.318 `hook_non_blocking_error`: raw model text in `stdout`, `JSON validation failed` in `stderr`, exit status 1, the literal unexpanded handler prompt in `command`, and execution timing. A valid denial prevents prompt admission instead.

Adapters with malformed raw model text can throw `ModelOutputError` from the engine entrypoint. Its raw text is retained only in opted-in private evidence and native artifacts, never dispatch diagnostics. Output budgets apply to this error path as well as returned decisions. Cancellation cannot admit a late result. Unsupported or unclassified failure evidence is rejected rather than converted into a command receipt or an empty history. Native provider/API-error rendering, model selection and transport behavior require their own service controls.

The [model artifact checks](../test/prompt-model-artifacts.test.ts) exercise admission, exact malformed-verdict fields, empty success/timeout attachments, snapshot restoration, privacy, output limits and cancellation. These core checks do not enable the default evaluator service or establish every handler/event/host combination.
